# Data Model: Console Todo Application

**Feature**: 001-console-todo
**Date**: 2025-12-29
**Phase**: Phase 1 - Data Modeling

## Overview

This document defines the data structures for the Console Todo Application. Given the Phase 1 constraint of in-memory storage only, the data model is intentionally simple, focusing on clear entity definitions and validation rules.

## Entities

### Task

**Purpose**: Represents a single todo item that a user wants to track.

**Implementation**: Python `@dataclass` (per Constitution III)

**Fields**:

| Field | Type | Required | Constraints | Default | Description |
|-------|------|----------|-------------|---------|-------------|
| `id` | `int` | Yes | Positive integer, unique, auto-generated | Auto-assigned | Unique identifier for the task, never reused after deletion |
| `title` | `str` | Yes | 1-200 characters, non-empty after strip | N/A | Brief description of the task |
| `description` | `str` | No | 0-1000 characters | `""` (empty string) | Optional detailed information about the task |
| `completed` | `bool` | Yes | True or False | `False` | Whether the task has been marked as complete |
| `created_at` | `datetime` | Yes | Valid datetime | Auto-assigned | Timestamp when the task was created |

**Validation Rules** (enforced in Storage layer, not in dataclass):

1. **Title Validation** (FR-021):
   - MUST NOT be empty after stripping whitespace
   - MUST NOT exceed 200 characters
   - Special characters allowed (all printable characters)
   - Whitespace trimmed before storage

2. **Description Validation** (FR-022):
   - MAY be empty (optional field)
   - MUST NOT exceed 1000 characters if provided
   - Special characters allowed
   - Whitespace preserved (not trimmed)

3. **ID Validation**:
   - Generated by storage layer, not user-provided
   - Starts at 1, increments for each new task
   - Never reused after deletion (FR-017)
   - Immutable after creation

4. **Completed Validation**:
   - Boolean only (True/False)
   - Defaults to False on creation (FR-004)
   - Toggled via dedicated operation (FR-018)

5. **Created At Validation**:
   - Generated automatically on task creation (FR-005)
   - Immutable after creation (FR-011)
   - Uses `datetime.now()` from Python standard library

**Immutability**:
- `id` and `created_at` are immutable after creation
- `title` and `description` can be updated via update operation (FR-010)
- `completed` can be toggled via toggle operation (FR-018)

**Example Instances**:

```python

from datetime import datetime

# Minimal task (title only)
Task(
    id=1,
    title="Buy groceries",
    description="",
    completed=False,
    created_at=datetime(2025, 12, 29, 10, 30, 0)
)

# Full task (with description)
Task(
    id=2,
    title="Complete hackathon project",
    description="Implement Phase 1 console todo app following SDD workflow",
    completed=False,
    created_at=datetime(2025, 12, 29, 10, 35, 15)
)

# Completed task
Task(
    id=3,
    title="Read Python documentation",
    description="Focus on dataclasses and typing modules",
    completed=True,
    created_at=datetime(2025, 12, 28, 14, 20, 45)
)
```

**String Representation**:
- Dataclass will implement `__str__` for readable console display
- Format: `Task(id={id}, title="{title}", completed={completed})`
- Used in confirmation messages and error reporting

### TaskStorage

**Purpose**: Manages the in-memory collection of tasks and provides CRUD operations.

**Implementation**: Python class with `dict[int, Task]` internal storage

**State**:

| Attribute | Type | Description |
|-----------|------|-------------|
| `_tasks` | `dict[int, Task]` | Internal dictionary mapping task IDs to Task instances |
| `_next_id` | `int` | Counter for generating unique task IDs, incremented on each add |

**Invariants**:

1. **Uniqueness**: No two tasks have the same ID
2. **ID Sequence**: IDs are strictly increasing (1, 2, 3, ...) with gaps allowed after deletions
3. **Non-Reuse**: Deleted task IDs are never reassigned to new tasks (FR-017)
4. **Consistency**: All tasks in `_tasks` have valid field values per validation rules

**Operations** (Public Methods):

#### add_task

```python
def add_task(self, title: str, description: str = "") -> Task:
    """
    Create and add a new task to storage.

    Args:
        title: Task title (1-200 characters, required)
        description: Task description (0-1000 characters, optional)

    Returns:
        The newly created Task instance

    Raises:
        ValidationError: If title is empty or exceeds 200 characters
        ValidationError: If description exceeds 1000 characters

    Side Effects:
        - Increments _next_id counter
        - Adds task to _tasks dictionary
    """
```

**Behavior**:
- Strips whitespace from title
- Validates title length (1-200 chars)
- Validates description length (0-1000 chars)
- Assigns ID from `_next_id`, then increments counter
- Sets `completed=False` and `created_at=datetime.now()`
- Returns created Task instance

---

#### get_all_tasks

```python
def get_all_tasks(self) -> list[Task]:
    """
    Retrieve all tasks in storage, ordered by ID.

    Returns:
        List of Task instances, sorted by ID (creation order)

    Side Effects: None (read-only)
    """
```

**Behavior**:
- Returns all tasks from `_tasks.values()`
- Sorted by ID (ascending order per FR-009)
- Returns empty list if no tasks exist

---

#### get_task_by_id

```python
def get_task_by_id(self, task_id: int) -> Task:
    """
    Retrieve a specific task by its ID.

    Args:
        task_id: The ID of the task to retrieve

    Returns:
        The Task instance with the specified ID

    Raises:
        TaskNotFoundError: If no task exists with the given ID

    Side Effects: None (read-only)
    """
```

**Behavior**:
- Looks up task in `_tasks` dictionary (O(1))
- Raises `TaskNotFoundError` if ID not found
- Used internally by update, delete, and toggle operations

---

#### update_task

```python
def update_task(
    self,
    task_id: int,
    title: str | None = None,
    description: str | None = None
) -> Task:
    """
    Update title and/or description of an existing task.

    Args:
        task_id: ID of the task to update
        title: New title (or None to keep current), 1-200 characters
        description: New description (or None to keep current), 0-1000 characters

    Returns:
        The updated Task instance

    Raises:
        TaskNotFoundError: If no task exists with the given ID
        ValidationError: If provided title/description violates constraints

    Side Effects:
        - Modifies task.title if title provided
        - Modifies task.description if description provided
        - Preserves task.id, task.completed, task.created_at (FR-011)
    """
```

**Behavior**:
- Retrieves task by ID (raises if not found)
- Validates new title/description if provided
- Updates only provided fields (partial update per FR-012)
- Preserves ID, completed status, and creation timestamp
- Returns updated Task instance

---

#### delete_task

```python
def delete_task(self, task_id: int) -> Task:
    """
    Permanently remove a task from storage.

    Args:
        task_id: ID of the task to delete

    Returns:
        The deleted Task instance (for confirmation display)

    Raises:
        TaskNotFoundError: If no task exists with the given ID

    Side Effects:
        - Removes task from _tasks dictionary
        - Does NOT decrement _next_id (IDs never reused per FR-017)
    """
```

**Behavior**:
- Retrieves task by ID (raises if not found)
- Removes task from `_tasks` dictionary
- Returns deleted task for confirmation message
- ID gap remains in sequence (e.g., if ID 5 deleted, next new task is ID 10, not ID 5)

---

#### toggle_complete

```python
def toggle_complete(self, task_id: int) -> Task:
    """
    Toggle the completion status of a task.

    Args:
        task_id: ID of the task to toggle

    Returns:
        The task with updated completion status

    Raises:
        TaskNotFoundError: If no task exists with the given ID

    Side Effects:
        - Flips task.completed (False → True or True → False)
    """
```

**Behavior**:
- Retrieves task by ID (raises if not found)
- Toggles `task.completed` boolean
- Returns updated task for confirmation message

## Custom Exceptions

### TaskNotFoundError

**Purpose**: Raised when an operation references a non-existent task ID.

**Base Class**: `Exception`

**Fields**:
- `task_id: int` - The ID that was not found

**Message Format**: `"Task with ID {task_id} not found"`

**Usage**:
- Raised by: `get_task_by_id`, `update_task`, `delete_task`, `toggle_complete`
- Caught by: CLI layer, displayed as user-friendly error message

---

### ValidationError

**Purpose**: Raised when user input violates data validation rules.

**Base Class**: `Exception`

**Fields**:
- `message: str` - Specific validation error description

**Message Examples**:
- "Title cannot be empty"
- "Title exceeds maximum length of 200 characters"
- "Description exceeds maximum length of 1000 characters"

**Usage**:
- Raised by: `add_task` (title/description validation), `update_task` (title/description validation)
- Caught by: CLI layer, displayed with retry prompt

## Data Flow & State Transitions

### Task Lifecycle

```
[Created]           add_task()
    ↓               → id assigned, completed=False, created_at set
[Active/Incomplete]
    ↓               toggle_complete()
[Completed]         → completed=True
    ↓               toggle_complete()
[Active/Incomplete] → completed=False (can toggle back)
    ↓               update_task()
[Updated]           → title/description changed, other fields preserved
    ↓               delete_task()
[Deleted]           → removed from storage, ID never reused
```

### Storage State Transitions

```
[Empty]             → _tasks={}, _next_id=1
    ↓ add_task()
[Contains Tasks]    → _tasks={1: Task(...)}, _next_id=2
    ↓ add_task()
[Multiple Tasks]    → _tasks={1: Task(...), 2: Task(...)}, _next_id=3
    ↓ delete_task(1)
[With ID Gaps]      → _tasks={2: Task(...)}, _next_id=3
    ↓ add_task()
[Gap Persists]      → _tasks={2: Task(...), 3: Task(...)}, _next_id=4
                      (ID 1 never reused)
```

## Persistence Constraints (Phase 1)

**Non-Persistent**: All data lives only in memory during application runtime.

**Implications**:
1. **On Application Start**: Storage is empty (`_tasks={}`, `_next_id=1`)
2. **During Runtime**: Tasks accumulate in memory
3. **On Application Exit**: All tasks are lost (per C-002)
4. **No Recovery**: No undo/redo, no backup (per Out of Scope)

**User Education**: Welcome message will state "In-memory only - data not saved between runs"

## Scalability & Performance

**Target Scale**: Up to 100 tasks per session (per A-004)

**Performance Characteristics**:

| Operation | Time Complexity | Space Complexity |
|-----------|----------------|------------------|
| add_task | O(1) | O(1) |
| get_all_tasks | O(n log n) | O(n) |
| get_task_by_id | O(1) | O(1) |
| update_task | O(1) | O(1) |
| delete_task | O(1) | O(1) |
| toggle_complete | O(1) | O(1) |

**Memory Usage** (estimated for 100 tasks):
- Task size: ~200 bytes per task (ID + strings + datetime + overhead)
- Total: ~20 KB for 100 tasks
- Negligible impact on modern systems

**No Optimization Needed**: O(1) dict operations handle 100 tasks trivially.
