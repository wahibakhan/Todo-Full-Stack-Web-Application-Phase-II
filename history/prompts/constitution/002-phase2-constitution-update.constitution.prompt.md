## Prompt

/sp.constitution # speckit.constitution
##  Standards for Phase 2: Full-Stack Web Application

### 1. Core Development Principles
- Spec-Driven Development is mandatory and non-negotiable.
- No manual coding is permitted. All code must be generated by agents based on approved specifications, plan, and tasks.
- Full traceability required: every line of code must map back to a specific section in speckit.specify, speckit.plan, or speckit.tasks.
- Prioritize security, maintainability, type safety, and clean architecture over rapid prototyping.

### 2. Phase 2 Scope and Technical Constraints
This phase delivers a secure, multi-user, persistent full-stack web application:
- Frontend: Next.js 16+ with App Router, TypeScript, Tailwind CSS
- Backend: Python FastAPI
- ORM: SQLModel
- Database: Neon Serverless PostgreSQL only
- Authentication: Better Auth with JWT tokens (shared BETTER_AUTH_SECRET)
- No console/CLI remnants from Phase 1
- No AI agents, MCP tools, Kafka, Dapr, Docker, or Kubernetes concepts
- No external libraries beyond those explicitly required by the tech stack

### 3. Architecture and Security Standards
- Monorepo structure with clear separation: /frontend, /backend, /specs
- Stateless authentication using JWT tokens
- Backend must verify JWT on every request and filter all queries by authenticated user_id
- User isolation enforced at database level (tasks table must have user_id foreign key)
- All API endpoints under /api/ and protected (401 Unauthorized without valid token)
- Environment variables mandatory for secrets (BETTER_AUTH_SECRET, DATABASE_URL)

### 4. Code Quality Standards
- Full type safety: TypeScript in frontend, Pydantic/SQLModel type hints in backend
- Modular design with separation of concerns
- Server Components by default in Next.js
- Clean API client abstraction in frontend (/lib/api.ts)
- Comprehensive error handling and meaningful HTTP status codes
- Defensive validation of all inputs
- Consistent naming, formatting, and documentation
- All changes must reference originating task ID in comments where applicable

### 5. Frontend Standards
- Responsive, professional UI using Tailwind CSS
- Authentication flows: signup, login, protected routes, logout
- Todo dashboard displaying only authenticated user's tasks
- Real-time feedback (loading states, success/error messages)
- Secure storage of JWT (httpOnly cookies preferred via Better Auth)

### 6. Backend Standards
- JWT verification middleware applied globally
- Dependency injection for database session
- SQLModel models reflecting exact database schema
- Routes organized logically with clear separation
- Proper use of HTTP exceptions for error cases

### 7. Specification and Documentation Compliance
- /specs folder must contain organized, up-to-date specifications for features, api, database, and ui
- Multiple CLAUDE.md files (root, frontend, backend) providing clear context
- README.md must include comprehensive local development and deployment instructions

### 8. Agent Conduct Rules
- Agents must not proceed to implementation without explicit approval of updated specifications, plan, and tasks for Phase 2
- Every code modification must be justified against Phase 2 requirements
- Agents must halt and request clarification on any ambiguity
- Source of truth hierarchy: Constitution > Specifications > Plan > Tasks

This constitution serves as the immutable foundation for Phase 2. Any proposed deviation requires formal amendment to this document and explicit approval.
